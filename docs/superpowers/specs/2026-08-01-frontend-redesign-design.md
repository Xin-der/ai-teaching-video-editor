# 前端重构设计：驾校内容优化工具 · 浅色商务风 MVP 产品站

> 日期: 2026-08-01 | 状态: 已定稿 | 范围: 纯静态前端（HTML/CSS/JS），后端零改动

---

## 一、背景与目标

v3 内容优化工具已开发完成并验证通过。当前前端 `web/templates/optimize.html` 是单页暗色工具界面（内嵌 CSS + 原生 JS），观感偏向开发者工具，不符合目标用户（驾校老板/运营，非技术人群）的信任感与使用习惯。

本次目标：在**功能与后端不变**的前提下，将前端重构成一个**标准单页 MVP 产品网站**，视觉参考 HeroUI（Tailwind 语义色变量、精心的留白/圆角/层级、浅蓝灰底 + 主色按钮）与市面优秀浅色商务后台（Docklight / Shadcn），走"简约大气、讲究留白"路线。

### 目标用户
- 驾校老板 / 运营（非技术人群，可能用手机）
- 页面职责单一：**选视频/贴文字 → 生成方案 → 照着复制发布**，同城获客

### 核心价值主张（5 秒看懂）
> 视频没人看？让 AI 把它改成能招生的内容——上传教学视频或粘贴文案，3 分钟拿到 5 块《内容优化方案》，照着改、照着发，抖音同城获客。

各区块职责：
- **导航栏**: 品牌 + 主 CTA（滚动到工具区），sticky 白底细边框

- **五块方案是什么**: 静态说明 5 块内容，建立预期与信任
- **Footer**: 极简版权行

## 三、视觉语言与设计 Token

参考 HeroUI（浅蓝灰底 + 语义色变量 + 精良留白/圆角/层级）与"简约商务蓝"浅色后台案例。

### 颜色

| Token | 值 | 用途 |
|-------|-----|------|
| `--bg` | `#F7F9FC` | 页面底色（浅蓝灰） |
| `--surface` | `#FFFFFF` | 卡片 / 导航 |
| `--border` | `#E5E7EB` | 细边框、分隔线 |
| `--text` | `#111827` | 标题 / 正文主色 |
| `--text-secondary` | `#4B5563` | 次级文字 |
| `--text-muted` | `#9CA3AF` | 弱文字 / 标签 |
| `--primary` | `#2563EB` | 主按钮、链接、强调 |
| `--primary-hover` | `#1D4ED8` | 主按钮 hover |
| `--primary-soft` | `#EFF6FF` | 选中 / 浅蓝底 |
| `--success` | `#16A34A` | 成功 toast |
| `--error` | `#DC2626` | 错误 toast / 文案 |

### 排版与间距
- 字体栈: `-apple-system, "PingFang SC", "Microsoft YaHei", "Segoe UI", system-ui, sans-serif`（不加载网络字体，CJK 过重 + 本地工具要稳要快）
- Hero 标题 28–32px 粗；区块标题 18–20px 粗；卡片标题 15–16px 粗；正文 14px；标签/弱文字 13px
- 行高 1.6；卡片内边距 24–28px；区块间距 40–48px；内容区最大宽 `~880px` 居中

### 形状与质感
- 圆角: 卡片 12–16px，按钮/输入 8–12px
- 卡片: 白底 + 细边框 + 柔和多层阴影（`0 1px 3px rgba(0,0,0,.05), 0 4px 12px rgba(0,0,0,.04)`）
- 按钮: 主按钮实心蓝 + 次按钮描边（HeroUI 风格）；主 CTA 可用轻微阴影提升层级

### 动效（克制）
- hover / `:focus-visible` 反馈；进度条动画；toast 滑入
- 尊重 `prefers-reduced-motion`

## 四、交互细节

- **输入卡片**: 上传区为虚线拖放区（点击选择，选中后显示文件名 + 大小）；"或粘贴文字" textarea；城市（可选）+ 平台（抖音）
- **生成按钮**: 无输入时禁用；提交后禁用并显示进度
- **进度**: 轮询 `/api/optimize/status`，动画条 + 后端返回的进度文案
- **结果渲染**: 5 块卡，对象字段显示**中文标签**（summary→诊断、issues→问题、strengths→优点、hook→开头3秒、body→主体、proof→证明、cta→引导、title→标题、cover_text→封面文字、description→简介、pinned_comment→置顶评论、profile_bio→主页简介、dm_opening→私信开场白）；next_topics 数组按"选题：标题 — 为什么"渲染
- **复制**: `navigator.clipboard` 复制格式化文本（保留现有 `fmtBlock` 逻辑）→ toast"已复制 ✅"
- **空/错误状态**: 空字段显示"（无）"；生成失败显示错误 toast + 按钮恢复可用 + 引导文案

## 五、文件变更

```
web/
├── app.py                    ← 零改动
├── templates/
│   └── optimize.html         ← 重写为页面骨架（区块结构 + link/css + script/js）
```

- 运行方式不变: `py run.py --web`（http://127.0.0.1:5000）

## 六、后端约束（不架空后端）

- 核心工具区 100% 接真实接口: `POST /api/optimize`（multipart 上传视频 / JSON 粘贴文字）与 `GET /api/optimize/status`（轮询）
- `web/app.py`、`engine/`、`tests/` **均不改动**
- 无假数据、无 mock

## 七、非目标（本次不做）

- 不引入构建步骤 / 框架（保持纯静态，零依赖，无需 Node）
- 不新增功能（不加历史记录、复制全部、下载 md）
- 不改后端接口与数据格式
- 不做收费、登录、多用户

## 八、验收标准

1. `py run.py --web` 启动后页面正常渲染，无 JS 报错
2. 文字模式真实调用生成一份方案（5 块齐全），每块可一键复制
3. 视频模式上传能提交（真实调用视网络/API 而定，功能通路正确）
4. 后端零改动，`py -3.12 tests/test_advisor.py` 10/10 通过
5. 响应式到手机宽度；键盘焦点可见；`prefers-reduced-motion` 生效
6. 页面观感: 浅色商务风、留白充分、无多余动画
