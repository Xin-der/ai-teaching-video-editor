# v4 设计：AI 内容教练工作台（模块化 + 全流程叙事 + 帧点评 + 选题灵感 + 部署）

> 日期: 2026-08-02 | 状态: 设计已定稿（P1 视觉按用户参考页 `example_html/index-min.html` 定稿；待用户审阅后进入实施计划） | 基线: v3.2（ASR 抗噪已完成）

---

## 一、背景与目标

v3/v3.1/v3.2 已完成：视频/文字 → 5 块《内容优化方案》的核心链路、浅色商务风单页产品站、SenseVoice 抗噪 ASR。

本次 v4 目标（产品经理视角与用户确认后的方向）：

1. **产品定位**: 架构做成"行业可配置"，**驾考仍是最先落地的垂直行业**（保留护城河），未来扩展行业只换配置文件、不改代码。
2. **产品形态**: 模块化功能 + 统一"AI 内容教练"品牌叙事，按**用户此刻的意图**组织入口，解决"功能关联性不强"的观感（不是靠强制工作流，而是靠叙事 + 信息架构）。
3. **P1 UI 重设计**: 页面布局与 UI 整体改版（信息架构已定；**视觉方向待用户提供参考图后定稿**）。
4. **P2 帧点评**: 自动挑出视频中"最有问题"的 2-3 帧，VLM 诊断（画质 + 内容表达），图上标注框 + 文字建议，直观告诉用户"哪里有问题、怎么改"。
5. **P3 选题灵感**: 精选选题库（即时可看）+ "AI 生成更多"（结合行业知识库 + 城市 + 季节/节点 + 热点半自动输入）。
6. **P4 部署 + 运维手册**: 试用阶段 CF Tunnel 免费方案（0 服务器费）+ 正式运营云服务器方案，两套运维手册；含跨平台改造。

### 目标用户（不变）
- 驾校老板 / 运营（非技术人群，可能用手机）
- 一次只做一个动作：优化已有视频，或不知道拍什么找选题

### 核心价值主张（升级）
> AI 内容教练——选题 → 拍摄 → 优化 → 发布，把你的视频变成学员。视频没人看？让 AI 把它改成能招生的内容。

### 3.2 设计决策

- **Tab 而非堆叠**: 优化视频（需视频输入）与选题灵感（无需视频）是两种不同意图；Tab 避免用户困惑"我在哪、该往哪填"。历史方案保留在工具区下方。
- **品牌叙事升级为"内容教练"**: 一句话串起三个模块（选题→拍摄→优化→发布），解决"关联性不强"——靠叙事与入口组织，不靠强制流程。
- **营销前置 + 工具直达**: 页面按参考页营销顺序铺排（建立信任与预期），但导航"开始使用"与 Hero"立即体验"**必须真实滚动到工具区并可直接使用**（非死链）。
- **行业可配置体现**: 页面文案、选题库、5块方案 prompt 全部走行业配置（默认 `driving_exam`）。

### 3.3 视觉方向（已定稿：采用参考页编辑风设计语言）

来源：用户提供 `example_html/index-min.html`，整体采用其**极简编辑风（editorial）**：无卡片、无阴影，发丝边框 + 大留白 + 超大排版 + 黑/橙双色。

**设计 Token（沿用参考，OKLCH）：**

| Token | 值 | 用途 |
|-------|-----|------|
| `--ink` | `oklch(20% 0.004 264)` | 近黑墨色：主文字 / 主按钮底 |
| `--ink-2` | `oklch(45% 0.004 264)` | 次级文字 |
| `--ink-3` | `oklch(62% 0.004 264)` | 弱文字 |
| `--ink-4` | `oklch(75% 0.004 264)` | 更弱 |
| `--line` | `oklch(90% 0.003 264)` | 发丝分隔线 |
| `--line-2` | `oklch(94% 0.002 264)` | 更淡分隔线 |
| `--paper` | `oklch(99% 0 0)` | 纯白纸面 |
| `--paper-2` | `oklch(97% 0.001 264)` | 浅灰底 |
| `--accent` | `oklch(55% 0.18 25)` | **暖橙强调**：hover、眉题、logo 点、帧标注框 |
| `--accent-soft` | `oklch(96% 0.03 25)` | 浅橙底（如选中态） |
| `--maxw` | `1080px` | 内容区最大宽 |
| 字体 | SF Pro / PingFang SC / Microsoft YaHei 系统栈 | 不加载网络字体 |

**排版：** Hero 标题 `clamp(44px,7vw,76px)` 负字距；区块标题 `clamp(32px,4.6vw,52px)`；正文 16-17px 行高 1.5；编号块序号 13px 大写字母距。

**组件：**
- 胶囊按钮（`border-radius:980px`），黑底白字，hover 转橙
- 编号块 01/02/03（营销五块与工具 5 块结果共用此排版），发丝分隔
- 导航 sticky + `backdrop-filter` 毛玻璃，logo 橙色小圆点
- 滚动渐显（IntersectionObserver `.reveal`），尊重 `prefers-reduced-motion`
- 工具区内（同套语言）：拖放区发丝虚线、进度为细线、结果用编辑编号行渲染（非卡片）、帧点评为图 + 橙色标注框 + 文字行

**与 v3.1 的关系：** 这是从"浅蓝灰 + 蓝 + 卡片阴影"整体切换为"墨黑 + 橙 + 编辑风"，`web/static/css/style.css` 需重写 token 与组件；功能逻辑 `app.js` 保留复用、按新结构改渲染。

## 四、P2 帧点评技术设计

### 4.1 数据流

```
上传视频 → pipeline._run_visuals() 已采样 ≤6 关键帧（复用，不新增采样成本）
  → 新模块 frame_diagnose：对采样帧批量请求 VLM"帧诊断"
     每帧返回：问题列表 + 严重度打分 + 标注框坐标 + 改进建议
  → 按 severity 选出 top 2-3 帧 → 并入方案 JSON
  → 前端渲染：图片 + 标注框 + 文字诊断卡片
```

### 4.2 VLM 输出 schema（qwen3.7-plus，坐标归一化 [x1,y1,x2,y2]）

```json
{ "frames": [
    { "index": 2,
      "problems": [
        { "category": "lighting",
          "label": "逆光",
          "box": [0.05, 0.1, 0.45, 0.6],
          "severity": 0.85,
          "advice": "主体过暗，建议朝光源拍摄或用补光灯" } ] } ] }
```

- `category`: 画质类（`lighting/blur/composition/focus`…）+ 内容表达类（`emphasis/content/visibility`…）
- 同帧多条问题都展示；框坐标越界/缺失 → 前端兜底只显示文字
- 图片降采样到 ~720p 后 **base64 内嵌 JSON** 返回（无临时文件生命周期管理）

### 4.3 组件与文件变更（预估）

```
engine/
├── frame_diagnose.py      ← 新增：帧诊断（VLM 调用 + 挑选 + schema 校验）
├── analyzer.py            ← 或在其内新增 diagnose_frames()
├── advisor.py             ← 编排：帧点评进 Web 展示；markdown 方案里仅文字诊断，不内嵌 base64 图片（避免文件过大）
web/
├── app.py                 ← /api/optimize 响应增加 frames 字段
├── static/js/app.js       ← 渲染图片 + 标注框 + 文字卡片
└── static/css/style.css   ← 标注框/卡片样式
```

### 4.4 降级与错误处理（关键）

- **VLM 帧诊断失败/超时 → 跳过帧点评，5 块方案照常出，绝不阻塞主流程**
- 框坐标缺失/越界 → 该问题只显示文字诊断
- 图片 base64 过大 → 降采样控制

### 4.5 测试

- 单测（mock VLM 返回带坐标诊断）：挑选逻辑取最严重、坐标归一化、schema 校验
- 前端：标注框渲染、无框兜底、加载态
- 集成：真实调用一次验证帧点评效果

## 五、P3 选题灵感技术设计

### 5.1 数据流

```
┌─ Tab 2【选题灵感】─────────────────────────────┐
│  精选选题库（静态 JSON，秒开，零 LLM 成本）     │
│    knowledge/driving_exam_topics.json          │
│    初始 10-20 条：考试季/招生季/新规/挂科点     │
│  ─────────────────────────────────            │
│  [AI 生成更多] 按钮                             │
│    POST /api/topics/generate                   │
│    参数：行业 + 城市 + 季节 + 热点(半自动字段)   │
│    → LLM 生成 [{标题, 说明, 为什么现在发, 拍摄思路}] │
└────────────────────────────────────────────────┘
```

### 5.2 关键设计

- **精选库**: 静态 JSON，`{id, title, description, category, tags, difficulty}`；初始人工 10-20 条驾考选题；AI 生成的优质选题可人工筛选入库
- **AI 生成更多**: `analyzer.py` 新增 `generate_topics()`，输入行业+城市+季节+热点，结合知识库生成一批，每条带**"为什么现在发"**和**拍摄思路**
- **热点半自动**: 界面一个可选字段"最近热点/想蹭的点"（运营者手动填）+ 城市/季节推导的节点（考试季/招生季）一起喂 LLM；**预留自动抓取接口位**
- **行业配置（轻量抽象，YAGNI）**: 新增 `engine/industry_config.py`，`get_industry_config(industry)` 返回该行业知识库/选题库/文案/prompt；仅实现 `driving_exam` 一份；**不迁移现有 `knowledge/driving_exam.json`**，有第二个行业再抽目录化

### 5.3 文件变更（预估）

```
engine/industry_config.py     ← 新增：行业配置接口（轻量）
engine/analyzer.py            ← 新增 generate_topics()
web/app.py                    ← 新增 /api/topics/generate + 静态选题库接口
knowledge/driving_exam_topics.json  ← 新增：精选选题库
web/static/js/app.js          ← Tab2 渲染 + 生成 + 复制
```

### 5.4 测试

- 选题库 schema 校验单测
- AI 生成 mock LLM 返回验证格式
- 前端 Tab2 渲染 + 复制

## 六、P4 部署 + 运维手册范围界定

### 6.1 两条路径

| | 路径 A：试用阶段（推荐） | 路径 B：正式运营 |
|---|---|---|
| 服务器 | **无**——本机跑 + Cloudflare Tunnel 暴露公网 | 云服务器（阿里/腾讯轻量 2核4G） |
| 费用 | 0 元（域名可选 ~30-70 元/年） | ~100 元/月（新用户首年可低到 99 元/年） |
| HTTPS | CF Tunnel 自带 | Caddy 自动 HTTPS 或 CF 反代 |
| 适用 | 1-2 家教练试用验证价值 | 价值验证后正式推广 |

### 6.2 跨平台改造（上云必做）

- ffmpeg 路径写死 `D:/Tools/...` → 改读环境变量/配置，兼容 Linux
- `RUN.bat`/`py -3.12` Windows 专属 → 通用启动脚本（`start.sh` / `start.bat` 双份）
- 路径拼接改用 `pathlib`

### 6.3 生产级服务（上云必做）

- Flask 开发服务器 → **waitress**（Windows/Linux 通用）
- 域名 + HTTPS：Caddy 自动签发
- DashScope Key 在服务端 `.env` 管理，**任何情况不进前端代码**

### 6.4 刻意不做（YAGNI，写进手册说明）

- **任务队列**: 试用单用户串行 + 现有 `/api/optimize/status` 轮询足够，不引入 Celery；多人并发再加
- **用户系统**: 历史方案现存 localStorage——公开部署后"每个浏览器各自独立、换设备看不到、无法区分用户"；试用可接受，**运维手册标注为已知限制**，正式运营前落服务端存储

### 6.5 运维手册内容清单（两套路径）

1. 部署步骤（依赖安装：Python 3.12 + ffmpeg + ASR 模型下载 + 环境变量）
2. 启动/停止/重启 + 开机自启
3. 日志查看与轮转
4. 常见故障排查表（ASR 模型下载失败 / 内存不足 / Key 失效 / CF 隧道掉线 / 端口占用）
5. 更新升级流程（`git pull` + 重启 + 验证）
6. **用户需要做的工作清单**（注册云服务商/买域名/装 cloudflared/配 .env…），每项标"你要做 / 我帮做"
